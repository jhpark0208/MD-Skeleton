# 07) 장애/실패 대응 프롬프트 (Debugger + Tester + Tech Lead)

목표:
오류 발생 시 에러 추적, 해결, 재검증을 SSOT 체계 안에서 처리한다.

입력:
- 실패 로그
- 실패 재현 스텝

실행 프롬프트:

```
실패 대응을 아래 순서로 수행해줘.

1) 실패 범위 분류: 계약 위반/아키텍처 위반/테스트 누락/구현 버그/요건 미일치
2) 1차 격리: 영향을 받는 scope, 파일, SSOT 항목 식별
3) 원인 가설 1~3개 작성
4) 각 가설별 최소 수정안 제시(설계 영향도/부작용 포함)
5) 수정 후 재검증 계획(테스트/로깅/계약 점검)
6) Tech Lead gate 필요성 판단(보안/아키텍처/품질 리스크)

출력:
- RCA(근본원인 추정)
- 수정안(우선순위 순)
- 회귀 위험
- 다음 handoff에 넣을 근거

규칙:
- 00% 추측 금지. 로그/증거 기반으로 추론.
- Escalation 필요 시 'Manager + Tech Lead' 라우팅을 명시.
